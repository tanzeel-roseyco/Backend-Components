# Security policy

## Supported code

Security fixes are provided for components classified as `production-ready` in
`components.json`. Reference and experimental components may receive fixes, but
they do not carry the same compatibility or response commitment.

## Reporting a vulnerability

Use the repository's **Security** tab and open a private security advisory. Do
not include credentials, customer data, exploit details, or an unpatched
vulnerability in a public issue.

Include the component path, affected versions or commits, impact, and a minimal
reproduction. Reports are acknowledged as capacity permits; this repository
does not currently promise a contractual response time.

## Adopting components

Consumers remain responsible for provider configuration, secret management,
authorization rules, database permissions, dependency updates, and deployment
controls in the application that adopts a component.
